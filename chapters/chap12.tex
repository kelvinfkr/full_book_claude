\section*{九百次比较教会机器人后空翻}

\storynote{Paul Christiano}{美国人工智能研究者。2017 年与 Jan Leike 等人在 DeepMind 与 OpenAI 合作发表《Deep Reinforcement Learning from Human Preferences》，用人类的两两比较训练奖励模型，再用强化学习优化——这套流程后来被称为 RLHF。2021 年他创立了对齐研究中心（ARC）。}

2017 年，一群研究者想让仿真里的一个单腿机器人（Hopper）做后空翻。麻烦在于：没人写得出"后空翻"的奖励函数。你可以奖励"离地高度"，得到的是原地蹦；你可以奖励"翻转角度"，得到的是躺在地上打滚。

他们换了个做法：让机器人随机做动作，把两段一两秒的视频放在一起，问一个普通人"哪段更像后空翻"。人只需要点一下鼠标。不到一千次这样的比较之后，机器人学会了一个干净利落的后空翻，而奖励函数从头到尾没人写过一行——它是从比较里\textbf{学}出来的。

五年后，同一套流程被用到语言模型上，做成了 InstructGPT（2022）和它的对话版本。人们给它起了一个名字：\textbf{基于人类反馈的强化学习}（RLHF）。又过了一年，DPO（2023）宣布"不需要奖励模型也能做到同样的事"；再一年，GRPO（2024）宣布"不需要价值网络也能训练推理模型"。

于是很多人把这段历史理解成一串工程配方：RLHF、DPO、GRPO，各有各的论文、各有各的技巧，学会一个再学下一个。

这是一个误解。

这三种方法解的是\textbf{同一个约束优化问题}：目标是奖励，约束是"别离出发点太远"，$\lambda$ 是这条约束的价格。它的最优解有闭式表达——正是第4章的玻尔兹曼分布。三种方法的差别只在于：谁负责估计奖励、谁负责近似这个分布。看清了这一点，你会发现"造训练数据的流水线"——生成、验证、过滤、去重——也是在解同一个问题，只是把"策略"换成了"数据分布"，把"奖励模型"换成了"验证器"。

\vspace{0.5cm}
\noindent\textit{为什么 DPO 不训练奖励模型，却能达到和 RLHF 一样的目标？为什么 GRPO 不需要价值网络？为什么一条数据流水线可以拆成互不相干的小模块，交给不同的人各写各的，拼起来照样能用？}

\begin{quote}
\textbf{本章目标}：把大模型与智能体的后训练——RLHF、DPO、可验证奖励与 GRPO、多步智能体的强化学习——以及为它们造数据的流水线，统一写成 $\Lag = f + \lambda^\top g$。你将看到：奖励是目标，"离参考策略的距离"与"验证器的判定"是约束，$\beta$ 与过滤强度 $\lambda$ 是它们的影子价格，而最优解永远是同一个玻尔兹曼分布。
\end{quote}

\section{从奖励到策略：RLHF 的目标函数}
% ------------------------------------------------------------------------------------

\subsection{三个阶段}

一个对话模型的诞生通常分三步。\textbf{预训练}：在海量文本上做下一个 token 预测（第11章）。\textbf{监督微调}（SFT）：在几万条人写的"问题--回答"上继续做极大似然，模型学会"以回答的格式说话"。\textbf{对齐}：让模型的回答更符合人的偏好——这一步就是本节的主角。

InstructGPT（2022）的做法是：先让标注者对同一个问题 $x$ 的两个回答 $y_1, y_2$ 说"哪个更好"，用这些比较训练一个\textbf{奖励模型} $r_\phi(x, y)$；然后把语言模型当作策略 $\pi_\theta(y \mid x)$，用强化学习最大化奖励。

但如果只最大化奖励，模型很快会找到奖励模型的漏洞：满篇讨好的套话、越写越长、甚至输出乱码——只要 $r_\phi$ 给高分。奖励模型是从有限数据里学出来的，离开训练分布就不可信。所以必须加一条约束：\textbf{别离出发点（SFT 模型）太远}。

\subsection{目标函数：奖励减去距离}

把 SFT 模型记为参考策略 $\pi_{\rm ref}$，RLHF 的目标函数是

\begin{keyformula}[title=RLHF 的目标函数]
\begin{equation}
    \begin{aligned}
    \max_{\theta}\quad J(\theta) = \;&\E_{x\sim\mathcal{D}}\,\E_{y\sim\pi_\theta(\cdot\mid x)}\big[r(x,y)\big] \\
    &-\; \beta\,\E_{x\sim\mathcal{D}}\Big[\mathrm{KL}\big(\pi_\theta(\cdot\mid x)\,\|\,\pi_{\rm ref}(\cdot\mid x)\big)\Big].
    \end{aligned}
    \label{eq:rlhf_obj}
\end{equation}
\end{keyformula}

用本书的眼光看，这已经是一个拉格朗日函数了。原问题是
\begin{equation}
    \max_\theta\ \E\big[r(x,y)\big] \quad \st \quad \E\big[\mathrm{KL}(\pi_\theta\,\|\,\pi_{\rm ref})\big] \le \delta,
\end{equation}
写出 $\Lag = \E[r] - \beta\,(\E[\mathrm{KL}] - \delta)$，常数 $\beta\delta$ 不影响优化，剩下的正是式~\eqref{eq:rlhf_obj}。$\beta$ 是 KL 约束的拉格朗日乘子：\textbf{KL 预算每多给 1 nat，最优期望奖励能多多少}。工程上没人给定 $\delta$ 再去解 $\beta$，而是直接调 $\beta$——这和第2章"给定价格、让市场自己找需求"的对偶做法一模一样。

\begin{tcolorbox}[colback=yellow!10, colframe=orange!80, title=本章的核心观点]
\textbf{后训练的每一种方法都在解同一个问题：最大化奖励，同时受"别离参考策略太远"的约束。}这个问题有闭式解 $\pi^* \propto \pi_{\rm ref}\,e^{r/\beta}$——第4章的玻尔兹曼分布，$\beta$ 是温度、$1/\beta$ 是乘子。RLHF 用采样逼近它，DPO 用对偶把奖励消掉直接学它，GRPO 用验证器代替奖励模型、用组内比较代替价值网络。造数据的流水线做的也是同一件事：从"参考分布 $\times$ 约束的玻尔兹曼权重"这个分布里采样。
\end{tcolorbox}

\subsection{闭式解：又是玻尔兹曼分布}

先固定一个 prompt $x$，把它从记号里省掉。把策略看成一个概率向量 $\pi(y)$，变量是它的每个分量，约束是归一化 $\sum_y \pi(y) = 1$。拉格朗日函数：
\begin{equation}
    \Lag(\pi, \alpha) = \sum_y \pi(y)\, r(y) \;-\; \beta \sum_y \pi(y) \log\frac{\pi(y)}{\pi_{\rm ref}(y)} \;-\; \alpha\Big(\sum_y \pi(y) - 1\Big).
\end{equation}
对 $\pi(y)$ 求导并令其为零：
\begin{equation}
    r(y) - \beta\Big[\log\frac{\pi(y)}{\pi_{\rm ref}(y)} + 1\Big] - \alpha = 0
    \quad\Longrightarrow\quad
    \pi(y) = \pi_{\rm ref}(y)\,\exp\!\Big(\frac{r(y) - \alpha}{\beta} - 1\Big).
\end{equation}
用归一化约束定出 $\alpha$，就得到
\review{第4章}{第4章的推导：在"期望约束"下最大化熵，解是 $p \propto e^{\beta g}$，乘子 $\beta$ 是逆温度。这里把"最大化熵"换成"最小化到 $\pi_{\rm ref}$ 的 KL"（第4章证明过两者是一回事），把 $g$ 换成奖励 $r$，得到的就是 $\pi^*$。"温度是乘子的倒数"再次成立。}

\begin{keyformula}[title=RLHF 的闭式解]
\begin{equation}
    \pi^*(y \mid x) = \frac{1}{Z(x)}\,\pi_{\rm ref}(y \mid x)\,\exp\!\Big(\frac{r(x,y)}{\beta}\Big),
    \label{eq:rlhf_closed}
\end{equation}
其中配分函数 $Z(x) = \sum_{y'} \pi_{\rm ref}(y' \mid x)\,e^{r(x,y')/\beta}$ 保证归一化。
\begin{equation}
    \text{等价地，}\quad \log \pi^*(y\mid x) = \log\pi_{\rm ref}(y\mid x) + \frac{r(x,y)}{\beta} - \log Z(x).
    \notag
\end{equation}
\end{keyformula}

\begin{physicalmeaning}[title=$\beta$ 是温度]
式~\eqref{eq:rlhf_closed}就是玻尔兹曼分布：$\pi_{\rm ref}$ 是"先验"，$-r$ 是"能量"，$\beta$ 是温度。
\begin{itemize}
    \item $\beta \to 0$（低温）：$\pi^*$ 把所有质量压到奖励最高的回答上——贪心，也最容易被奖励模型的漏洞带偏。
    \item $\beta \to \infty$（高温）：$\pi^* \to \pi_{\rm ref}$，什么都没学。
    \item 中间的 $\beta$：$\pi^*$ 在参考策略上做一次"按奖励重加权"。乘子 $1/\beta$ 越大，奖励的话语权越大。
\end{itemize}
$\pi(y)\ge 0$ 的不等式约束从头到尾没有起作用——指数永远是正的，所以这些约束的乘子全是零（第1章的互补松弛）。
\end{physicalmeaning}

一阶条件还有一种读法。把它整理成
\begin{equation}
    r(y) - \beta \log\frac{\pi^*(y)}{\pi_{\rm ref}(y)} = \beta \log Z \quad \text{对所有 } y \text{ 成立}.
    \label{eq:equal_after_price}
\end{equation}
左边是"奖励减去按价格 $\beta$ 折算的 KL 花费"。最优点的特征是：\textbf{扣掉价格之后，每个回答都一样好}。这和第1章的经济学解释是同一件事——在最优配置下，每单位资源的边际收益相等。

\subsection{PPO-RLHF 在做什么}

闭式解在手，为什么还需要强化学习？因为 $y$ 是一个 token 序列，可能的回答有 $|\mathcal{V}|^T$ 个，配分函数 $Z(x)$ 算不出来，我们只能\textbf{从 $\pi_\theta$ 采样来逼近这个解}。

InstructGPT 式的做法：把 KL 惩罚写进奖励，
\begin{equation}
    \tilde r(x, y) = r_\phi(x, y) - \beta\big[\log \pi_\theta(y \mid x) - \log \pi_{\rm ref}(y \mid x)\big],
\end{equation}
然后用第9章扩展阅读里的 PPO 最大化 $\E[\tilde r]$：采样一批回答，估计优势，用裁剪的重要性比做几轮小步更新。一个技术细节：序列的对数概率是各 token 对数概率之和，所以 KL 惩罚也可以逐 token 地加到奖励上，让价值网络学一个"逐 token 的影子价格"。
\think{把式~\eqref{eq:equal_after_price}和 $\tilde r$ 放在一起看：当 $\pi_\theta = \pi^*$ 时，$\tilde r(y)$ 对所有 $y$ 相等，于是优势恒为零、策略梯度的方差也为零。这意味着什么？提示：本章实验一里 PPO-KL 曲线最后掉到 $10^{-7}$ 以下，不是巧合。}

\begin{insightbox}[title=两个 KL，两个乘子]
PPO-RLHF 里同时出现两个 KL，别混淆：
\begin{itemize}
    \item 第9章扩展阅读里 TRPO/PPO 的信赖域 $\mathrm{KL}(\pi_{\rm old}\,\|\,\pi_\theta) \le \delta$，是相对\textbf{上一步}的策略，乘子决定\textbf{步长}；
    \item 本章式~\eqref{eq:rlhf_obj}的 $\mathrm{KL}(\pi_\theta\,\|\,\pi_{\rm ref})$，是相对\textbf{固定的参考策略}，乘子 $\beta$ 决定\textbf{终点}——最终解离出发点多远。
\end{itemize}
外层的 $\beta$ 定义要解的问题，内层的裁剪负责一步步走过去：一个是问题的一部分，一个是求解器的一部分。
\end{insightbox}

代价是工程上的：训练时内存里同时住着四个模型——策略、参考策略、奖励模型、价值网络——而且每一步都要让策略生成完整的回答。附录C会算这笔显存账。这也是 DPO 与 GRPO 各自想省掉的东西：DPO 省掉奖励模型和采样，GRPO 省掉价值网络。

\section{DPO：把奖励用对偶消掉}
% ------------------------------------------------------------------------------------

\subsection{反解奖励}

式~\eqref{eq:rlhf_closed}是"给定奖励，求策略"。把它倒过来读——"给定最优策略，奖励是什么"——两边取对数：
\begin{equation}
    r(x, y) = \beta \log\frac{\pi^*(y \mid x)}{\pi_{\rm ref}(y \mid x)} + \beta \log Z(x).
    \label{eq:reward_from_policy}
\end{equation}
这说明：\textbf{任何奖励函数都可以用"它诱导的最优策略"来表示}，差一个只依赖 $x$ 的常数 $\beta\log Z(x)$。奖励与策略之间是一一对应的（在"相差一个只依赖 $x$ 的常数"的意义下）。

\subsection{代入偏好模型，配分函数消掉}

奖励模型是怎么从比较里训练出来的？标准做法是 Bradley--Terry 模型（1952）：两个回答里 $y_w$ 胜过 $y_l$ 的概率是
\begin{equation}
    P(y_w \succ y_l \mid x) = \sigma\big(r(x, y_w) - r(x, y_l)\big), \qquad \sigma(u) = \frac{1}{1 + e^{-u}}.
\end{equation}
它只依赖\textbf{奖励之差}。把式~\eqref{eq:reward_from_policy}代进去，两个 $\beta\log Z(x)$ 正好相减抵消：
\begin{equation}
    P(y_w \succ y_l \mid x) = \sigma\Big(\beta\log\frac{\pi^*(y_w\mid x)}{\pi_{\rm ref}(y_w\mid x)} - \beta\log\frac{\pi^*(y_l\mid x)}{\pi_{\rm ref}(y_l\mid x)}\Big).
\end{equation}
右边只剩策略，没有奖励、没有配分函数。于是可以直接用参数化的策略 $\pi_\theta$ 去拟合人类的比较数据——极大似然：

\begin{keyformula}[title=DPO 损失（2023）]
\begin{equation}
    \mathcal{L}_{\rm DPO}(\theta) = -\,\E_{(x, y_w, y_l)\sim\mathcal{D}}\bigg[\log\sigma\Big(\underbrace{\beta\log\frac{\pi_\theta(y_w\mid x)}{\pi_{\rm ref}(y_w\mid x)}}_{\hat r_\theta(x, y_w)} - \underbrace{\beta\log\frac{\pi_\theta(y_l\mid x)}{\pi_{\rm ref}(y_l\mid x)}}_{\hat r_\theta(x, y_l)}\Big)\bigg].
    \label{eq:dpo}
\end{equation}
$\hat r_\theta = \beta\log(\pi_\theta/\pi_{\rm ref})$ 叫做\textbf{隐式奖励}：策略本身就是一个奖励模型。
\end{keyformula}

它的梯度很有启发性：
\begin{equation}
    \begin{aligned}
    \nabla_\theta \mathcal{L}_{\rm DPO} = -\beta\,\E\Big[&\underbrace{\sigma\big(\hat r_\theta(x,y_l) - \hat r_\theta(x,y_w)\big)}_{\text{隐式奖励排错了的程度}} \\
    &\cdot\big(\nabla_\theta\log\pi_\theta(y_w\mid x) - \nabla_\theta\log\pi_\theta(y_l\mid x)\big)\Big].
    \end{aligned}
\end{equation}
提高 $y_w$ 的概率、压低 $y_l$ 的概率，权重是"当前隐式奖励把这一对排错了多少"——排对了的样本几乎不再产生梯度。

\begin{keyidea}[DPO 的目标 / 约束 / $\lambda$]
\textbf{目标}：偏好数据的对数似然（Bradley--Terry）。

\textbf{约束}：与 RLHF 完全相同——$\mathrm{KL}(\pi_\theta\,\|\,\pi_{\rm ref})$ 不能太大。只是这条约束没有显式出现：它被"用 $\beta\log(\pi_\theta/\pi_{\rm ref})$ 参数化奖励"这一步吸收进了变量替换里。

\textbf{$\lambda$}：还是 $\beta$。它现在出现在 $\sigma(\cdot)$ 里面，控制隐式奖励的尺度：$\beta$ 越大，同样的对数概率比对应越大的奖励差，策略只需离参考策略很近就能解释数据。
\end{keyidea}
\clarify{DPO 的 $\beta$ 与 RLHF 的 $\beta$ 是同一个乘子，不是巧合：DPO 就是把 RLHF 的闭式解代入偏好似然。所以如果你在 DPO 里把 $\beta$ 从 0.1 调到 0.5，等价于在 RLHF 里把 KL 惩罚系数调大五倍——最终解会更贴近 $\pi_{\rm ref}$。}

\subsection{第2章的重演：换个角度看问题}

第2章讲对偶时说过一句话：约束优化有两套变量，原始变量 $x$ 和乘子 $\lambda$；有时候从乘子那边看问题反而简单。RLHF 与 DPO 就是这句话的一个漂亮实例：
\begin{itemize}
    \item RLHF 走的是"先求奖励、再求策略"：奖励模型 $r_\phi$ 是中间量，策略靠采样与策略梯度逼近式~\eqref{eq:rlhf_closed}。
    \item DPO 注意到式~\eqref{eq:reward_from_policy}是一个\textbf{变量替换}：奖励空间与策略空间一一对应。既然最终要的是策略，就在策略空间里直接做极大似然，奖励作为中间量被消掉。
\end{itemize}
第1章说过，处理约束有两条路——"代入消元"和"引入乘子"。DPO 是代入消元：它利用一阶条件把奖励用策略表出，就像第17章的流匹配把噪声与数据之间的路径固定成直线、从而不必给它配乘子一样。

代价也要说清楚。DPO 的偏好对是\textbf{离线}的（通常由 $\pi_{\rm ref}$ 生成再由人标注），训练时不从当前策略 $\pi_\theta$ 采样；而 RLHF 是在线的，策略每改一步，下一批样本就来自新策略。第9章讲过这两者的区别：离线数据的覆盖决定了你能学到什么。实践中也观察到 DPO 可能同时压低 $y_w$ 和 $y_l$ 的概率——只要两者的\textbf{差}在变大，损失就在下降。在本章实验一里，这个差别表现为：DPO 的曲线在有限偏好对决定的噪声地板上停住，而在线的 PPO-KL 一路降到底。

\section{可验证奖励与 GRPO}
% ------------------------------------------------------------------------------------

\subsection{验证器：只回答"可不可行"}

奖励模型的根本问题是它是\textbf{学}出来的：它有盲区，策略会找到盲区。但有一大类任务的奖励不需要学：
\begin{itemize}
    \item 数学题：最终答案和标准答案比对，对得 1 分，错得 0 分；
    \item 代码：跑单元测试，全过得 1 分；
    \item 机器人任务：物体是否到了指定位置，由传感器或仿真器判定。
\end{itemize}
这类奖励叫\textbf{可验证奖励}：由一段程序而不是一个网络给出，取值通常是 $\{0, 1\}$。用本书的语言，它不是目标函数 $f$，而是\textbf{约束} $g$——它只回答"这条轨迹可不可行"，不回答"好多少"。可验证奖励几乎不能被"钻空子"（答案对了就是对了），这正是 2024 年以来用强化学习训练推理模型的基础。

\subsection{GRPO：组内比较，不要价值网络}

有了 0/1 奖励，再看第9章的策略梯度：$\nabla J = \E[(r - b)\nabla\log\pi_\theta]$，基线 $b$ 用来降方差，PPO 用价值网络 $V(s)$ 当基线。GRPO（2024）的观察是：既然可以对\textbf{同一个} prompt 采样很多次，那么这一组回答的平均得分就是现成的基线，不需要另外训练一个价值网络。

对 prompt $x$，从旧策略采样一组 $G$ 个回答 $y_1, \ldots, y_G$，各自的可验证奖励为 $r_1, \ldots, r_G$。

\begin{keyformula}[title=GRPO 的简化更新式]
\begin{equation}
    \begin{aligned}
    A_i &= r_i - \bar r, \qquad \bar r = \frac{1}{G}\sum_{j=1}^G r_j, \\
    \theta &\leftarrow \theta + \eta\,\frac{1}{G}\sum_{i=1}^G A_i\,\nabla_\theta\log\pi_\theta(y_i \mid x) \;-\; \eta\,\beta\,\nabla_\theta\widehat{\mathrm{KL}}(\pi_\theta\,\|\,\pi_{\rm ref}).
    \end{aligned}
    \label{eq:grpo}
\end{equation}
原始论文还把 $A_i$ 除以组内标准差、对 token 取平均，并像 PPO 一样用裁剪的重要性比做多轮更新；KL 项用逐样本的估计 $\widehat{\mathrm{KL}} = \frac{\pi_{\rm ref}(y_i)}{\pi_\theta(y_i)} - \log\frac{\pi_{\rm ref}(y_i)}{\pi_\theta(y_i)} - 1$（它逐样本非负，常称 k3 估计）。
\end{keyformula}

当 $r_i \in \{0, 1\}$ 时，$\bar r$ 就是这一组的成功率 $\hat p$，更新式变成
\begin{equation}
    \frac{1}{G}\Big[(1 - \hat p)\sum_{i:\ r_i = 1}\nabla\log\pi_\theta(y_i) \;-\; \hat p\sum_{i:\ r_i = 0}\nabla\log\pi_\theta(y_i)\Big].
\end{equation}
读一读它：\textbf{对成功的回答做加权的极大似然，对失败的回答做加权的"反极大似然"}。如果一组全对（$\hat p = 1$）或全错（$\hat p = 0$），梯度恰好为零——太容易和太难的题都不提供信号，这是实践中要按难度筛题的原因。

\begin{lstlisting}[language=Python, caption={GRPO 一步更新的核心（本章实验一的玩具版，单个 prompt、$K$ 个离散回答）}]
y = torch.multinomial(pi_old, groups * G, True).view(groups, G)
rew = r[y]                                  # 可验证奖励（查表代替判题）
adv = rew - rew.mean(dim=1, keepdim=True)   # 组内均值作基线
logp = torch.log_softmax(theta, 0)[y]
ratio = torch.exp(logp - logp_old)          # 重要性比
surr = torch.min(ratio * adv,
                 torch.clamp(ratio, 1 - clip, 1 + clip) * adv)
lr_ref = log_pi_ref[y] - logp               # log(pi_ref / pi_theta)
k3 = torch.exp(lr_ref) - lr_ref - 1.0       # KL 的 k3 估计（非负）
loss = -(surr - beta * k3).mean()
\end{lstlisting}

\subsection{对应第9章：对偶上升 vs 原始改进}

第9章用最短路讲了两种求解思路：\textbf{对偶上升}维护乘子（值函数）并保证最优性，\textbf{原始改进}维护可行解并一步步改进。把它套到这里：
\begin{itemize}
    \item PPO-RLHF 带价值网络，是对偶上升的路子：先估计每个状态的影子价格 $V(s)$，再据此改进策略；价值网络学不准，策略就被带偏。
    \item GRPO 是原始改进的路子：验证器只判断"可行 / 不可行"，不给任何价值估计；策略改进完全靠"采样一组、留下可行的、提高它们的概率"。没有对偶变量，也就没有对偶变量学错的风险；代价是方差大，需要大批量采样（第9章"为什么选择蒙特卡洛"的旁注说的就是这件事）。
\end{itemize}
\sidenoteplain{\textbf{验证器不是奖励模型。}奖励模型 $r_\phi$ 试图逼近"好多少"，是目标函数的替身；验证器只判定"对不对"，是约束。前者可以被优化者利用（Goodhart 定律：一个指标一旦成为目标，就不再是好指标），后者不会——但它的信号也更稀疏：一道题只有 0 和 1。}

式~\eqref{eq:grpo}的 KL 项让 GRPO 仍然在解式~\eqref{eq:rlhf_obj}那个问题：目标是可验证奖励的期望，约束是别离参考策略太远，$\beta$ 还是那个价格。一个有意思的细节留给习题：k3 估计逐样本求导得到的梯度，其期望并不是 $\nabla\mathrm{KL}(\pi_\theta\,\|\,\pi_{\rm ref})$，而是反向的 $\nabla\mathrm{KL}(\pi_{\rm ref}\,\|\,\pi_\theta)$。所以 GRPO 的不动点与 $\pi^*$ 有一个小小的、可以精确算出来的偏差——实验一会把它画出来。

\subsection{实验一：三种方法，同一个玻尔兹曼分布}

把"语言模型"压缩到最小：一个 prompt，$K = 10$ 种可能的回答，策略是 $\pi_\theta(y) = \mathrm{softmax}(\theta)_y$。随机给定参考策略 $\pi_{\rm ref}$ 与奖励向量 $r \in [0,1]^{10}$，取 $\beta = 0.5$，闭式解 $\pi^*$ 可以直接算出来。然后分别用三种方法从 $\theta_0 = \log\pi_{\rm ref}$ 出发训练 300 步：
\begin{itemize}
    \item \textbf{PPO-KL}：每步从 $\pi_\theta$ 采 256 个回答，KL 惩罚写进奖励，批均值作基线，裁剪的重要性比做 4 轮更新；
    \item \textbf{DPO}：从 $\pi_{\rm ref}$ 采 4000 对回答，按 Bradley--Terry 概率 $\sigma(r(y_1) - r(y_2))$ 抽签决定胜负（去掉相同的对后剩 3179 对），全批梯度下降最小化式~\eqref{eq:dpo}；
    \item \textbf{GRPO}：每步采 16 组、每组 16 个回答，组内均值作基线，k3 估计的 KL 项，裁剪比做 4 轮更新。
\end{itemize}

\section{多步智能体的强化学习}

\subsection{工具调用是一个 MDP}

前面的"回答"是一次生成。真正的智能体要跟环境来回打交道：查资料、调用计算器、执行一段代码、看返回结果、再决定下一步。这是一个标准的马尔可夫决策过程，只是各项的含义换了：
\begin{center}
\renewcommand{\arraystretch}{1.3}
\small
\begin{tabular}{@{}p{3.0cm}p{2.8cm}p{6.1cm}@{}}
\toprule
& \textbf{第9章的 MDP} & \textbf{多步智能体} \\
\midrule
状态 $s_t$ & 棋盘局面 / 机器人位姿 & 当前上下文：指令 + 已生成的文字 + 工具返回的结果 \\
动作 $a_t$ & 落子 / 关节力矩 & 一段话，或一次工具调用（函数名 + 参数） \\
转移 $s_{t+1} = f(s_t, a_t)$ & 物理规则 & 环境把工具的返回值追加到上下文（外部、随机、可能有副作用） \\
奖励 $r_t$ & 每步都有 & 稀疏：通常只在最后由验证器给出 0/1 \\
\bottomrule
\end{tabular}
\end{center}
第9章的整套语言原封不动地搬过来：动力学是约束，值函数（的梯度）是它的乘子，贝尔曼方程是一阶条件。区别在于\textbf{奖励极其稀疏}——二十步工具调用之后才知道任务成没成功。

\subsection{信用分配：回到 TD / MC 权衡}

最后一步得了 1 分，功劳该记给哪一步？这就是信用分配问题，第9章用"决策深度"这个维度讨论过它：
\begin{itemize}
    \item \textbf{蒙特卡洛}：整条轨迹的回报归给每一步。无偏，但方差随步数增长。GRPO 默认就是这样——一组轨迹，成功的整条提概率，失败的整条压概率。
    \item \textbf{时序差分}：用价值网络 $V(s_t)$ 估计"从这一步起还能拿多少"，只把一步的差分 $r_t + \gamma V(s_{t+1}) - V(s_t)$ 归给这一步。方差小，但 $V$ 学错了就有偏差。
    \item \textbf{广义优势估计}（GAE）：用一个参数在两者之间插值，第9章扩展阅读里 PPO 的实现就用它。
\end{itemize}
\clarify{GAE 里的那个插值参数在文献里也记作 $\lambda$，与本书的拉格朗日乘子 $\lambda$ 毫无关系——它只是在"用估计值"和"用真实回报"之间取一个加权平均。本书所说的乘子，在这一节里是价值网络 $V(s_t)$：状态 $s_t$ 的影子价格。}

用本书的语言重说一遍：价值网络就是在\textbf{估计每一步状态的影子价格} $\partial J^*/\partial s_t$（第9章"$\lambda$ 在本章的意义"盒子）。信用分配的两难，就是"直接观测目标（MC）"与"估计乘子（TD）"的两难——第9章最短路里 Bellman-Ford 与 Dijkstra 的两难。

\subsection{过程奖励与结果奖励}

既然中间步骤没有奖励，能不能人为地给？\textbf{过程奖励模型}（PRM）对推理链的每一步打分——这一步的推导对不对、这次工具调用是否合理；\textbf{结果奖励}（ORM，或验证器）只看最后。两者的取舍正是本章反复出现的那对矛盾：
\begin{itemize}
    \item 过程奖励信号密集，相当于给每一步一个价值估计（乘子的估计），信用分配容易；但它是学出来的（或人标的），会被钻空子，标注也贵。
    \item 结果奖励稀疏、方差大，但如果它来自验证器，就几乎不可能被钻空子。
\end{itemize}
实践中常见的折中是：结果奖励来自验证器（硬约束，不可协商），过程奖励只作为辅助信号加一个较小的权重——又一个 $\lambda$。第14章 PINN 里"边界条件的权重要不要自适应"的讨论，在这里会再次出现。

最后一点在多步智能体里比在单轮对话里重要得多：动作有\textbf{副作用}。一次工具调用可能删文件、发邮件、下订单。安全约束 $h(s_t) \ge 0$ 于是从第16章的机器人走到了软件智能体身上，它的乘子——安全的价格——不能靠奖励模型来估，得靠硬性的权限边界。第17章讨论真机强化学习时，同一条约束会以更物理的形式出现。

\section{造数据的流水线：从约束分布采样}
% ------------------------------------------------------------------------------------

\subsection{生成、验证、过滤：一个分布的三个因子}

后训练缺的从来不是算法，是数据。人写的示范贵而少，于是人们让模型自己造：一个\textbf{生成器}产出候选，一个\textbf{验证器}判断对错，一个\textbf{过滤器}只留下合格的，再拿它们去训练——训练出来的模型又成为下一轮的生成器。这套流程有很多名字：拒绝采样微调、专家迭代（2017）、自我训练。它们看起来是工程，其实是一个干净的数学问题。

设生成器给出提议分布 $p(x)$，验证器计算违约量 $g(x) \ge 0$（$g = 0$ 表示可行）。我们想要的是"在 $p$ 附近、但满足约束"的分布 $q$。用第4章的语言把它写成约束优化：
\begin{equation}
    \min_q\ \mathrm{KL}(q\,\|\,p) \quad \st \quad \E_q[g(x)] \le \varepsilon, \qquad \sum_x q(x) = 1.
\end{equation}
拉格朗日乘子法（与本章第一节的推导逐字相同，只是 $r$ 换成 $-g$、$\beta$ 换成 $1/\lambda$）给出

\begin{keyformula}[title=数据流水线的目标分布]
\begin{equation}
    q_\lambda(x) = \frac{1}{Z}\,p(x)\,\exp\big(-\lambda\,g(x)\big).
    \label{eq:pipeline_dist}
\end{equation}
\begin{itemize}
    \item \textbf{按分数加权}（软约束）：给每个样本权重 $w(x) = e^{-\lambda g(x)}$，就是从 $q_\lambda$ 采样——又是玻尔兹曼分布，$\lambda$ 是违约量的价格。
    \item \textbf{硬过滤}：令 $\lambda \to \infty$，权重变成 $\mathbbm{1}[g(x) = 0]$，只留可行样本——这正是\textbf{拒绝采样}。
\end{itemize}
\end{keyformula}

三句话概括：\textbf{过滤器就是约束，过滤强度就是乘子，加权采样就是玻尔兹曼分布}。式~\eqref{eq:pipeline_dist}与式~\eqref{eq:rlhf_closed}是同一个式子——$\pi_{\rm ref}$ 变成生成器 $p$，奖励 $r$ 变成 $-g$，温度 $\beta$ 变成 $1/\lambda$。RLHF 在策略空间里做的事，数据流水线在数据空间里做。

\subsection{迭代：把"策略改进"交给数据选择}

现在让学生模型 $p_1$ 在筛出的数据上做极大似然，再用 $p_1$ 当生成器，重复 $n$ 轮。如果学生每轮都拟合得很好，那么
\begin{equation}
    p_n(x) \;\propto\; p_{n-1}(x)\,e^{-\lambda g(x)} \;\propto\; p_0(x)\,e^{-n\lambda\,g(x)}.
    \label{eq:pipeline_iter}
\end{equation}
\review{第2章}{第2章的对偶上升：$\lambda_{k+1} = \lambda_k + \rho\,g(x_k)$——约束还没满足，价格就继续涨。式~\eqref{eq:pipeline_iter}是它的"数据版"：每轮迭代都把价格 $\lambda$ 加到累计乘子上。硬过滤则是一开始就把价格定成无穷大。}
这个式子说了两件事。第一，\textbf{软加权迭代 $n$ 轮，等价于一次乘子为 $n\lambda$ 的软加权}：乘子逐轮累加，分布逐轮向可行域收缩，$n \to \infty$ 时也趋于硬过滤。第二，它是第9章\textbf{策略迭代}的翻版——"策略评估"由验证器完成（算 $g$），"策略改进"由数据选择完成（按 $e^{-\lambda g}$ 重加权后做极大似然）。GRPO 那个"对成功的回答做极大似然"的更新式，正是这个流程的在线、单步版本。

\begin{keyidea}[数据流水线的目标 / 约束 / $\lambda$]
\textbf{目标}：留在生成器 $p$ 附近——$\mathrm{KL}(q\,\|\,p)$ 最小。离得太远，样本就不再像模型自己会写的东西，训练时学不动；也保留了 $p$ 的多样性。

\textbf{约束}：验证器的判定 $\E_q[g] \le \varepsilon$。可以有很多条：格式对不对、答案对不对、长度是否合规、与已有数据是否重复——每条一个 $g_j$。

\textbf{$\lambda$}：每条约束一个乘子 $\lambda_j$，目标分布是 $q \propto p\,\prod_j e^{-\lambda_j g_j}$。$\lambda_j \to \infty$ 是硬过滤（答案错了就扔），有限的 $\lambda_j$ 是打分加权（风格差一点，降权但不扔）。
\end{keyidea}

\subsection{为什么各个模块可以独立开发}

一条真实的流水线有很多环节——生成、格式检查、答案验证、质量打分、去重——往往由不同的人写、在不同的机器上跑、各自版本更新。为什么拼起来还能用？式~\eqref{eq:pipeline_dist}给出了答案：\textbf{约束是可分离的}。
\begin{equation}
    q(x) \;\propto\; p(x)\,\underbrace{e^{-\lambda_1 g_1(x)}}_{\text{格式}}\;\underbrace{e^{-\lambda_2 g_2(x)}}_{\text{答案}}\;\underbrace{e^{-\lambda_3 g_3(x)}}_{\text{质量}}\;\cdots
\end{equation}
拉格朗日函数是 $f + \sum_j \lambda_j g_j$，每条约束一项、彼此相加；对应到分布上就是每个模块一个因子、彼此相乘。每个模块只需要正确地算出自己那个 $g_j$，不需要知道别的模块的存在；调整某条约束的严格程度，只动它自己的 $\lambda_j$。这就是流水线能"各写各的"的数学原因——它与第2章讲的"对偶分解"（把耦合的大问题按约束拆成独立的小问题）是同一个原理。

唯一不可分离的是\textbf{去重与多样性}：它不是对单个样本的约束，而是对整个分布的约束（例如"熵不能低于某个值"）。式~\eqref{eq:pipeline_iter}已经警告过：每轮迭代都在收缩分布，$n$ 轮之后熵只会更低。反复用自己生成的数据训练自己而不加多样性约束，分布会越缩越窄——这就是近年讨论的"模型坍缩"。多样性约束的乘子是温度：它给分布"加热"，正好抵消验证器一轮轮的"降温"。

\subsection{实验二：最小数据流水线}

把上面的流程做成一个几十秒就能跑完的实验。\textbf{生成器}是一个小自回归网络，把二维点当成长度为 2 的"句子"：先输出 $x$ 落在 40 个格子中的哪一个，再以 $x$（的傅里叶特征）为条件输出 $y$ 的格子，格子内均匀抖动；最后一层初始化为零，所以第 0 轮它是 $[-2, 2]^2$ 上的均匀分布——一个什么都不懂的模型。\textbf{验证器}是一段程序：点落在环 $1.0 \le |x| \le 1.3$ 内为可行，违约量 $g$ 是到环的距离。\textbf{过滤器}有两种：硬过滤只留可行点；软加权给每个点权重 $e^{-\lambda g}$。\textbf{学生}与生成器同结构，在（加权的）样本上做极大似然，然后接替生成器。每轮生成 4000 个点，迭代 5 轮。
\tryit{改 data\_pipeline.py 里的 R\_IN、R\_OUT，把环换成两个分离的小圆盘，看硬过滤会不会只学会其中一个（模式坍缩）。再把 angular\_entropy 换成"落在两个盘里的比例"，画出它随轮数的变化。}

\section{机器人的数据引擎}
% ------------------------------------------------------------------------------------

语言模型的数据流水线便宜：生成一条回答只要几毫秒，验证一道数学题只要比对答案。机器人的三件事都贵：\textbf{生成}一条轨迹要真机跑几十秒（或者要一个足够真的仿真器），\textbf{验证}"任务成功了吗"要从图像里判断，而且约束里多了一条谁也绕不开的\textbf{物理}——动作必须是机器人做得出来的。于是围绕机器人形成了一整套"数据引擎"，每个模块都在为式~\eqref{eq:pipeline_dist}提供\textbf{样本}或提供\textbf{约束}。

\subsection{五个模块}

\paragraph{示教扩增} 人类遥操作示教是最贵的数据。MimicGen（2023）一类方法的想法是：一条示教可以按物体切成若干段（伸向物体、抓起、移到目标处），每一段的动作是相对于物体位姿定义的；换一个物体初始位姿，把各段做刚体变换再拼接，就得到一条新轨迹。拼出来的轨迹在仿真里回放，\textbf{只保留任务成功的}——几十条人类示教由此扩成上千条。用本章的语言：示教给出 $p_0$，位姿扰动是提议分布，仿真回放是验证器，成功判定是硬过滤。

\paragraph{用语言模型生成任务与场景} RoboGen、GenSim（2023）一类工作让大语言模型去写任务描述、生成仿真场景的配置、甚至写出成功判定函数与奖励函数的代码。这一类模块提供的不是样本而是\textbf{约束}：它们在造新的 $g$——新任务、新场景、新的成功条件——让流水线不只是在一个固定任务上收缩，而是在任务空间里扩张。生成的代码可以执行，就是一个可验证的东西：跑不通的场景自动丢掉。

\paragraph{世界模型 rollout} 第16章的潜空间动力学模型学会了"做梦"：在潜空间里从当前状态展开一段未来。做梦比真机便宜几个数量级，于是世界模型成了生成器。它的问题在验证器那一侧：梦里的成功不一定是真的成功，模型自己的预测误差就是一条新约束——只有在模型可信的区域（第16章图里"预测误差贴着噪声水平"的那段视界内）采到的样本才能用。一个常见做法是把"模型的不确定性"也写成违约量、给它一个乘子。

\paragraph{VLM 自动打成功标签} 真机轨迹跑完了，成没成功谁来判？让第11章的视觉--语言模型看最后一帧（或整段视频）回答"杯子在洗碗机里吗"。这是一个\textbf{学出来的验证器}——比程序验证器灵活，能判断"把桌子收拾干净"这种没有精确定义的任务，但也会犯错。所以它的乘子是有限的：VLM 给的标签应当作为软加权而不是硬过滤，或者用多次询问、多个模型投票来降低错误率。
\preview{第17章会把这条回路闭合：HIL-SERL 一类系统里，示教起步、离策略强化学习、人类随时接管纠正、图像奖励分类器判定成败——纠正片段与成功片段一起回流进经验池。那时你会看到，"人的接管"同时是生成器（示范正确动作）、验证器（"我接管了"就是失败信号）和安全约束的乘子。}

\paragraph{真机数据回流} 最后，部署出去的机器人每天都在产生轨迹。这些数据来自真实分布（没有仿真与真实的差距），但没有标签、大多是平淡无奇的成功、偶尔有失败。回流的价值恰恰在失败上：它们标出了当前策略的可行域边界在哪里——用第1章的话说，它们告诉你哪些约束是\textbf{紧}的。

\begin{unification}[title=统一视角：策略、数据、约束]
本章从头到尾只有一个分布：
\[
q(x) \;\propto\; p(x)\,\exp\Big(-\sum_j \lambda_j g_j(x)\Big).
\]
RLHF / DPO / GRPO 里，$p$ 是参考策略，$-g$ 是奖励或验证器，$1/\lambda$ 是 $\beta$，$q$ 是要训练出的策略。数据流水线里，$p$ 是生成器，$g_j$ 是各个验证器与打分器，$q$ 是要造出来的数据集。机器人的数据引擎里，各个模块要么在给 $p$ 提供样本，要么在给 $g_j$ 提供定义。目标是什么（留在 $p$ 附近）、约束是什么（$g_j$）、$\lambda$ 代表什么（违约的价格）——三个问题问下来，任何一个新模块都能找到自己的位置。
\end{unification}

\section{本章小结}
% ------------------------------------------------------------------------------------

让我们回顾这一章的核心内容：

\begin{enumerate}
    \item \textbf{RLHF 的目标函数是一个拉格朗日函数}：$\E_\pi[r] - \beta\,\mathrm{KL}(\pi\,\|\,\pi_{\rm ref})$，奖励是目标，"别离参考策略太远"是约束，$\beta$ 是它的价格。闭式解 $\pi^* \propto \pi_{\rm ref}\,e^{r/\beta}$ 是第4章的玻尔兹曼分布，$\beta$ 是温度，$1/\beta$ 是乘子。最优点处"扣掉价格之后每个回答一样好"。PPO-RLHF 用采样逼近这个解。

    \item \textbf{DPO 是对偶消元}：从闭式解反解 $r = \beta\log(\pi^*/\pi_{\rm ref}) + \beta\log Z$，代入 Bradley--Terry 偏好模型，$Z$ 消掉，得到只含策略的损失。不学奖励、直接学策略，是第2章"换个角度看问题"和第1章"代入消元"的重演；代价是离线数据。

    \item \textbf{可验证奖励是约束，不是目标}：验证器只回答"可不可行"。GRPO 对同一题采样一组回答、组内均值作基线、不要价值网络——这是第9章的"原始改进"：没有对偶变量，靠采样与筛选改进策略；0/1 奖励下它就是"对成功的回答做极大似然、对失败的做反向"。

    \item \textbf{多步智能体是稀疏奖励的 MDP}：状态是上下文，动作是一句话或一次工具调用，奖励只在最后。信用分配回到 TD/MC 权衡，价值网络估计的是每一步状态的影子价格；过程奖励密集但可被利用，结果奖励稀疏但来自验证器不可协商。

    \item \textbf{数据流水线是从约束分布采样}：$q \propto p\,e^{-\lambda g}$，硬过滤是 $\lambda \to \infty$，打分加权是有限 $\lambda$。迭代 $n$ 轮等价于乘子累加到 $n\lambda$——对偶上升的数据版；策略迭代里的"策略改进"交给了数据选择。约束可分离，所以模块可以各写各的；唯一不可分离的是多样性，它的乘子是温度。

    \item \textbf{机器人的数据引擎}：示教扩增、语言模型生成任务与场景、世界模型 rollout、VLM 自动打标、真机回流，每个模块要么提供样本、要么提供约束，都在为同一个分布服务。
\end{enumerate}

\begin{physicalmeaning}[title=$\lambda$ 在本章的意义]
本章的约束是"离出发点不能太远"与"验证器必须通过"，它们的乘子有两个名字：
\[
\beta = \frac{\partial J^*}{\partial \delta}\ \text{（KL 预算的价格）}, \qquad
\lambda = -\frac{\partial\,\mathrm{KL}^*}{\partial \varepsilon}\ \text{（违约量的价格）},
\]
两者互为倒数：$\beta = 1/\lambda$。
含义：\textbf{允许策略（或数据分布）多偏离参考分布 1 nat，期望奖励能多 $\beta$；要求违约量再降 1 单位，得付出 $\lambda$ 的 KL}。
\begin{itemize}
    \item 第4章：同一个乘子叫逆温度；本章的 $\beta$ 是温度，$1/\beta$ 才是乘子——"温度是乘子的倒数"
    \item 第9章：TRPO 的 KL 乘子决定步长，本章的 $\beta$ 决定终点；价值网络是状态的影子价格，GRPO 用组内比较绕开了估计它
    \item 第2章：软加权迭代 $n$ 轮，乘子累加到 $n\lambda$——对偶上升的数据版
    \item 第14章：PINN 的罚系数 $\rho$ 与自适应权重 $\lambda$，和本章"硬过滤 vs 软加权"是同一个取舍
    \item 第17章：真机上安全约束的乘子不能靠奖励模型估，要靠人的接管与硬性边界
\end{itemize}
\end{physicalmeaning}

\paragraph{计算题}
\begin{enumerate}
    \item 三个回答的参考策略 $\pi_{\rm ref} = (0.5, 0.3, 0.2)$，奖励 $r = (0, 1, 2)$。分别计算 $\beta = 0.5, 1, 4$ 时的闭式解 $\pi^*$、它的熵，以及 $\mathrm{KL}(\pi^*\,\|\,\pi_{\rm ref})$。验证：$\beta$ 越小，KL 越大、熵越小。

    \item 对上题 $\beta = 1$ 的 $\pi^*$，验证式~\eqref{eq:equal_after_price}：$r(y) - \beta\log[\pi^*(y)/\pi_{\rm ref}(y)]$ 对三个 $y$ 都等于 $\beta\log Z$。

    \item 设 $J^*(\delta) = \max\{\E_\pi[r] : \mathrm{KL}(\pi\,\|\,\pi_{\rm ref}) \le \delta\}$。用包络定理说明 $\mathrm{d}J^*/\mathrm{d}\delta = \beta$，并在上题的例子里用数值差分验证（提示：对一系列 $\beta$ 算出 $(\delta, J^*)$，再对 $\delta$ 做差分）。

    \item GRPO 一组 $G = 8$ 个回答里有 3 个正确。写出每个回答的优势 $A_i = r_i - \bar r$；若再除以组内标准差，优势变成多少？说明为什么"全对"或"全错"的组梯度为零。
\end{enumerate}

\paragraph{证明题}
\begin{enumerate}
    \setcounter{enumi}{4}
    \item 证明：对固定的 $\pi_{\rm ref}$ 与 $\beta > 0$，映射 $r \mapsto \pi^*$（式~\eqref{eq:rlhf_closed}）把"相差一个只依赖 $x$ 的常数"的奖励映到同一个策略，且这是唯一的等价关系（即两个奖励诱导同一策略当且仅当它们相差一个只依赖 $x$ 的常数）。由此解释为什么 DPO 里 $Z(x)$ 必然消掉。

    \item 证明 DPO 的梯度公式：$\nabla_\theta\mathcal{L}_{\rm DPO} = -\beta\,\E[\sigma(\hat r_\theta(y_l) - \hat r_\theta(y_w))(\nabla\log\pi_\theta(y_w) - \nabla\log\pi_\theta(y_l))]$。

    \item （k3 估计的方向）设 $y \sim \pi_\theta$，逐样本量 $k_3(y) = \frac{\pi_{\rm ref}(y)}{\pi_\theta(y)} - \log\frac{\pi_{\rm ref}(y)}{\pi_\theta(y)} - 1$。证明 $\E_{y\sim\pi_\theta}[k_3] = \mathrm{KL}(\pi_\theta\,\|\,\pi_{\rm ref})$，但把样本视为固定、对 $\theta$ 求导后再取期望，得到的是 $\nabla_\theta\mathrm{KL}(\pi_{\rm ref}\,\|\,\pi_\theta)$。由此写出 GRPO（组内均值基线）的不动点所满足的方程，并说明它与 $\pi^*$ 的差别在 $\beta \to \infty$ 与 $\beta \to 0$ 时各趋于什么。

    \item 证明式~\eqref{eq:pipeline_iter}：若每轮学生都精确拟合加权经验分布，则 $p_n \propto p_0\,e^{-n\lambda g}$；进一步证明 $p_n$ 的熵关于 $n$ 单调不增（提示：$p_n$ 是 $p_0$ 在"$\E[g] \le \varepsilon_n$"约束下的最小 KL 投影，$\varepsilon_n$ 递减）。
\end{enumerate}
